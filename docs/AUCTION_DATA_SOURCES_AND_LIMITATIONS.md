# Аукционы: источники данных и ограничения автоматической проверки

Этот документ объясняет простым языком, откуда Жертап берёт сведения по аукционному участку и в каких случаях автоматическая проверка **не должна** делать предположений.

Последнее обновление: 2026-08-29.

## Главное правило

Жертап не подменяет отсутствие официальных данных догадкой.

- «Не найдено в опубликованном слое» не равно «ограничения точно нет».
- «Кадастровый номер отсутствует» не равно «это другой участок».
- Любое сопоставление должно хранить источник, дату получения и основание связи.

## Три ключа одного участка

Один участок может появляться в разных торгах E-Qazyna с разными номерами лота. Для объединения используется строгое правило, в порядке доверия:

1. **EGKN ID** — идентификатор участка из официальной карточки.
2. **Полный кадастровый номер** — только полный номер; маски, `-`, `_` и обрывки не являются ключом.
3. **Jerler object ID** — стабильный числовой идентификатор в публичной ссылке Jerler:
   `.../objects/list/<Jerler ID>/view`.

Если ни одного ключа нет, Жертап не объединяет лот с другим объектом автоматически.

## Когда в лоте нет кадастрового номера

Это нормальная ситуация для части аукционных карточек.

### Что Жертап делает

- не пытается угадывать кадастровый номер по названию, площади, району или координатам;
- не запускает прямой поиск в ЕГКН **по кадастру**, потому что ключа для такого поиска нет;
- сохраняет стабильный Jerler ID и polygon, если они доступны в официальной карточке Jerler;
- использует polygon для GIS-проверок только как контур из Jerler с явно указанным источником;
- если позднее в Jerler появился EGKN ID или полный кадастр, дополняет canonical объект этим официальным идентификатором.

### Что Жертап не утверждает

Без полного кадастра или EGKN ID система не утверждает, что polygon из Jerler юридически совпадает с записью ЕГКН. В карточке такой случай должен оставаться: **«требуется ручная сверка с официальными документами»**.

## Роли источников

| Источник | Что берём | Чего не обещаем |
|---|---|---|
| E-Qazyna | лот, цена, статус, документы, дата торгов, ссылка на объект | кадастр и GIS-ограничения есть не у каждого лота |
| Jerler | EGKN ID/кадастр при наличии, право, срок аренды, polygon, часть условий | не заменяет юридическую сверку и не всегда содержит кадастр |
| ЕГКН | кадастровый поиск и границы при наличии официального идентификатора | не используется для угадывания участка; не считается единственным источником генплана/ПДП/красных линий |
| НИПД map.gov.kz | опубликованные национальные/муниципальные пространственные слои, например водоохранные зоны | отсутствие объекта в одном слое не является юридическим заключением |
| Муниципальные геопорталы | генплан, ПДП, красные линии и местные зоны там, где они опубликованы в GIS | доступность и актуальность отличаются по городам; источник/версия обязательны |
| gov.kz документы | утверждённые документы, ПДП, решения и приложения | PDF/скан без геометрии требует документной или ручной проверки |

## GIS-проверки

Для автоматического пересечения нужны одновременно:

1. polygon участка с источником;
2. официальный GIS-слой с геометрией;
3. понятная семантика слоя и версия/дата;
4. проверка пересечения геометрий.

Если хотя бы одного компонента нет, результат: **«не проверено автоматически»**, а не «ограничений нет».

### Водоохранные зоны

Жертап умеет запрашивать опубликованный слой НИПД `geonode:waterprotectionzone` по bbox участка и считать площадь пересечения. Даже при отсутствии пересечения вывод остаётся нейтральным:

> В опубликованном слое пересечение не найдено. Требуется ручная проверка применимого акта и полноты покрытия.

## Статусы, которые должны быть понятны пользователю

- **Подтверждено источником** — есть конкретный официальный источник и дата.
- **Обнаружено пересечение** — геометрии пересеклись; это предупреждение, не юридическое решение.
- **Не найдено в опубликованном слое** — слой ответил, но это не clearance.
- **Не проверено автоматически** — нет polygon, слоя, покрытия или источник недоступен.
- **Требуется ручная сверка** — нужен акт, документ, техническое условие либо проверка в органе.

## Текущий порядок расширения

1. Сохранять единый объект участка и polygon с provenance.
2. Подключать только официальные GIS-слои с воспроизводимым запросом.
3. Сначала показывать evidence/предупреждение, не юридический вывод.
4. После проверки качества слоя добавлять его в автоматические red flags.
5. Для неоцифрованных генпланов и ПДП сохранять ссылку/документ и показывать ручную проверку.
