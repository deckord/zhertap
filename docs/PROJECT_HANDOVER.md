# Land Scout Kazakhstan: общий handover

Документ нужен, чтобы новый системный администратор, разработчик или новый чат Codex быстро понял проект без чтения старой переписки.

История production-изменений, причин инцидентов и проверок после исправлений ведется в [CHANGELOG_LOGIC.md](CHANGELOG_LOGIC.md). Перед расследованием нового сбоя сначала проверьте этот журнал.

## Назначение проекта

Land Scout Kazakhstan - публичный сайт, личный веб-кабинет, Telegram-бот и операторская веб-панель для двух направлений:

1. Поиск расчетных мест под земельный участок для ЛПХ/садоводства.
2. Мониторинг и аналитика земельных аукционов E-Qazyna.

Проект не является государственным сервисом, торговой площадкой или юридическим подтверждением свободной земли. Он делает предварительный информационный анализ по открытым источникам и показывает ориентиры для дальнейшей проверки через акимат, земельные органы, E-Qazyna и осмотр на местности.

Актуальный простой статус по `Аукционы v2`: [AUCTIONS_V2_STATUS.md](AUCTIONS_V2_STATUS.md).

## Основные службы

В Docker Compose поднимаются:

- `web` - FastAPI-приложение, админка, API, webhook ApiPay.
- `bot` - Telegram-бот на aiogram.
- `worker` - Celery worker для тяжелых задач поиска, платежных проверок и синхронизации аукционов.
- `beat` - Celery Beat, периодически запускает синхронизацию E-Qazyna.
- `db` - PostgreSQL/PostGIS.
- `redis` - брокер и backend Celery.

## Основные пользовательские сценарии

### 0. Сайт и личный кабинет

Пользователь:

1. Открывает `https://zhertap.kz`.
2. Видит публичную страницу с продажным позиционированием “многоэтапный анализ территории”: ЕГКН, промежутки, дороги/объекты, площадь, ПДП при наличии слоя и полный отчет.
3. Регистрируется по номеру телефона: SMS-код отправляется через SMSC один раз для подтверждения номера.
4. После верного SMS-кода задает пароль.
5. Дальше входит по телефону и паролю без постоянных SMS-расходов.
6. При регистрации обязательно принимает оферту и условия сервиса; версия оферты, дата, IP и User-Agent сохраняются.
7. Новый веб-аккаунт получает 1 день полного тестового доступа, если `TRIAL_ACCESS_ENABLED=true`.
8. После новой регистрации в кабинете может появиться необязательный интерактивный тур; клиент может нажать `Не проходить`, и тур больше не показывается.
9. В кабинете есть постоянная страница `/cabinet/help` с простой инструкцией: что выбирает пользователь, как система проверяет ЕГКН, открытые карты, генплан/ПДП и почему результат предварительный.
10. В кабинете можно привязать Telegram к тому же аккаунту.
11. Веб и Telegram используют один доступ: новый оплаченный доступ действует 1 месяц от даты оплаты; legacy-доступ без даты окончания остается активным.
12. В кабинете доступны обзор, анализ территории, инструкции, аукционы, избранное, сравнение, подписки, обратная связь, настройки и смена пароля.
13. Если по выбранной территории нет пригодного цифрового слоя генплана/ПДП, веб-кабинет и Telegram-отчет дают ссылку на официальный документ или геопортал для ручной сверки.
14. Статус генплана/ПДП показывается клиенту человеческим языком: `Генплан/ПДП проверен автоматически`, `Генплан/ПДП не подключен`, `Генплан/ПДП не подтвердил это место` или `Генплан/ПДП ожидает проверки`. Сырые внутренние статусы `passed`, `waived`, `blocked`, `pending` не должны попадать в клиентский UI без пояснения.
15. В веб-кабинете клиенту показываются только кандидаты, прошедшие обязательные проверки (`approved/approved_with_note` и `passed/waived` по генплану). Кандидаты, которые ЕГКН нашел предварительно, но генплан/ПДП отклонил, остаются в базе и админке для диагностики, но не выводятся клиенту как предлагаемые участки.

### 1. Поиск места под участок

Пользователь:

1. Открывает бота.
2. Выбирает язык: русский или казахский.
3. Принимает условия.
4. Выбирает раздел поиска места под участок.
5. Выбирает назначение: ЛПХ, ЛПХ(новый поиск), садоводство. Для садоводства доступны расчетные профили 6 и 12 соток; для ЛПХ нового поиска — 15/25 соток.
6. Выбирает область, район, населенный пункт или поиск по всем районам.
7. Бот создает заявку.
8. Worker выполняет многоэтапный анализ и ищет расчетные места.
9. Если есть генплан/ПДП, проверяет по нему. Если пригодного слоя нет, система автоматически продолжает без генплана и явно пишет это в отчете; ручная кнопка остается fallback.
10. Первые бесплатные участки выдаются автоматически.
11. После лимита бот предлагает единый доступ.
12. После оплаты доступ действует 1 месяц для этого Telegram user ID; после окончания включается ограниченный режим и можно оплатить новый месяц.
13. Пользователь может запрашивать следующие 10 участков без повторной оплаты; уже отправленные варианты не повторяются.
14. В веб-кабинете статус анализа обновляется через polling, без ручного обновления страницы, с видимыми этапами обработки.

### 2. Аукционы

Пользователь:

1. Открывает раздел земельных аукционов.
2. Выбирает регион, назначение, цену и площадь.
3. Получает список официальных лотов E-Qazyna.
4. Первый полный лот доступен бесплатно.
5. После оплаты единого доступа открываются все лоты, избранное, сравнение и уведомления.
6. Можно открыть источник E-Qazyna, документы, историю торгов, изменения и краткую аналитику.
7. Можно сохранить лоты в избранное и сравнить до 10 лотов.
8. Можно подписаться на новые лоты по фильтрам.
9. В веб-кабинете регион, район, населенный пункт и назначение выбираются из справочников.

### 3. Обратная связь

Клиент может написать обратную связь через Telegram или веб-кабинет. Администратор работает в `/admin/feedback`: видит диалоги, платежный статус клиента, историю рассылок, ответы клиентов и может отвечать клиенту в Telegram. Новые клиентские сообщения поднимаются вверх, выделяются как непрочитанные и имеют счетчик.

## Что уже умеет система

### Поиск ЛПХ/садоводства

- Справочники областей, районов и населенных пунктов ЕГКН.
- Поиск по конкретному населенному пункту.
- Поиск по району, если у городского района нет отдельного списка населенных пунктов.
- Поиск по всем районам/населенным пунктам с ограничением выдачи.
- Геометрическая проверка, что квадрат нужной площади помещается между зарегистрированными участками.
- Поиск соседнего кадастрового номера как ориентира.
- Проверка OSM: дороги, здания, вода, кладбища, инфраструктурные и иные исключающие объекты.
- Проверка загруженных официальных геопривязанных слоев генплана/ПДП.
- Genplan-first поиск: если для выбранной территории есть активные разрешающие полигоны генплана/ПДП, геометрический поиск сначала сужает район/населенный пункт до этих зон и только потом грузит ЕГКН.
- Садоводство ищется отдельно от ЛПХ: 12 соток как максимальная бесплатная норма, 6 соток как мягкий профиль для плотных садовых массивов. С 04.08.2026 садоводство проверяется по отдельным активным слоям `Садоводство` в 6 региональных Smart GeoHub-группах; ЛПХ 10 соток использует уже активное семейство `ЛПХ:household`.
- Автопродолжение без проверки генплана, если официального пригодного слоя нет; учет покрытия хранится в `urban_plan_coverage`.
- Кнопки повтора ошибки без повторного выбора параметров.
- Бесплатный лимит по количеству участков, а не по количеству заявок.
- Единый платный доступ для поиска участков и аукционов.
- Celery Beat каждые 5 минут восстанавливает зависшие `processing` заявки, pending free preview и готовые, но не доставленные уведомления.

### Генпланы/ПДП

- Хранение слоев `allowed`, `prohibited`, `red_line`.
- Учет покрытия по территории/назначению в `urban_plan_coverage`.
- Проверка, что расчетный квадрат целиком попадает в разрешающую зону.
- Проверка запретных зон и красных линий с буфером.
- Импорт GeoJSON через админку.
- Конвейер подготовки релизов слоев через инструменты `tools/genplan_*`.
- Ручная операторская проверка завершена: обработаны все 641 кандидатные точки, `queued = 0`. Это отдельный законченный этап; он не зависит от backlog новых источников и легенд.
- Production active coverage на 17.08.2026: 111 активных строк `VERIFIED_STRICT/search` в 37 областях применения. Дополнительно включены Уральск, Жезказган, Алатау (`household` и `field`), Сарыөзек Кербулакского района и Талдыкорган (`household` и `gardening`). Локальный генплан имеет приоритет над региональным fallback.
- Production totals: 426 строк `urban_plan_layers`: 111 активных `VERIFIED_STRICT/search`, 99 `SUPERSEDED`, 216 `REVIEWED_HOLD`; необработанных `WARNING` нет.
- Все прежние 336 shadow/QA-строк разобраны. Отдельный будущий backlog — 1313 записей легенд `needs_review` и 344 источника `not_imported`; это новые исходные материалы, а не неразобранные цифровые слои или ручные точки.
- Последний подробный production-аудит генпланов/ПДП находится в `docs/GENPLAN_STATUS_2026_08_17.md`.
- Важно: широкий слой, который подходит только по metadata, но не покрывает найденные точки геометрией, не должен блокировать весь выбранный район. В таком случае заявка идет как предварительная без автоматической проверки генплана.
- Кокшетау и Актау пытались собрать из AIS GGK 29.07.2026, но safety gate заблокировал импорт: Кокшетау из-за отброшенных allowed-геометрий, Актау из-за `Point` в red-line.
- Если пригодного официального слоя нет, система автоматически продолжает анализ без генплана и явно пишет это в отчете. Если слой есть, но сломан/спорный или кандидат попал в запрет/красную линию, автоматического обхода нет.
- Клиентские тексты статуса генплана централизованы в `app/urban_plan_labels.py` и используются в веб-деталях заявки, polling JSON и Telegram-отчетах. Страница `/cabinet/searches/{id}` дополнительно имеет fallback, чтобы не падать `500`, если часть контекста не передана старой веткой.
- Админская очередь `/admin` не показывает сырой `SearchRequest.status` как единственное объяснение. `ready` - только технический статус "поиск завершен, нужен следующий шаг"; оператор видит человекочитаемые статусы через `admin_search_status()`: `Участки не найдены`, `Найдено, ждёт отправки`, `Ждёт оплаты`, `Оплачено, не отправлено`, `Отчёт отправлен`, `Сбой поиска`.
- В `/admin/analytics` фактические Telegram-счета, оплаты и доставленные платные отчеты считаются по `search_requests`, потому что событие `payment_paid` может не создаться, если ApiPay подтвердил оплату уже доставленной заявки. Блок `Сайт` считает только `account_payments` веб-аккаунтов; бесплатные админские доступы `0 KZT` не считаются реальной оплатой.

### Аукционы

- Синхронизация E-Qazyna по статусам из `EQAZYNA_SYNC_STATUSES`.
- Хранение карточек лотов, документов, истории публикаций и изменений.
- Расчет цены за сотку и квадратный метр.
- Сравнение с районной средней ценой.
- Автоматический рейтинг 0-100 без ИИ.
- Статистика по регионам, районам, категориям и месяцам.
- GeoJSON API для карты активных лотов.
- Расстояния по открытым данным, если координаты и reference objects доступны.
- Избранное.
- Подписки на новые лоты по региону, району, населенному пункту, назначению, цене и площади.
- Уведомления об изменениях избранных лотов.
- Закрытый `/cabinet/auctions-v2` для администратора: единая лента, справочники регион/район/населенный пункт, карточка проверки лота, блок решения перед участием, карта, источники и диагностика.
- `Аукционы v2` пока не считается завершенной единой платформой: нужно добить полноту E-Qazyna, gov.kz/акиматы, ЕГКН/кадастр, геопорталы, историю торгов и полноценный Telegram v2.

## Важные ограничения

- Пустое место на ЕГКН не доказывает юридическую свободу земли.
- Кадастровый номер в отчете - это номер соседнего зарегистрированного участка, а не номер свободного участка.
- Генплан проверяется автоматически только там, где загружен и включен официальный геопривязанный слой `VERIFIED_STRICT`.
- PDF/JPG генпланы без геопривязки не используются как автоматическое доказательство.
- Google Maps не используется через официальный API для юридической проверки.
- Данные OSM могут быть неполными.
- Аукционная история не является полной ретроспективой всех лет, пока не выполнен отдельный исторический backfill.
- Окончательные решения принимают акимат, земельные органы, E-Qazyna и осмотр на местности.
